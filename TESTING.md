# Проверки CarCar 1.0.0

Фактическое окружение: Windows 11 Pro x64 10.0.26200, установлен Microsoft WebView2. Сборка: Rust 1.100.0 MSVC, Tauri 2.12.7, React 19, TypeScript, Vite 6.

## Автоматические проверки

- `npm run build`: TypeScript и production frontend — успешно. Начальный JS около 238 КБ; Markdown и CodeMirror загружаются из встроенных ресурсов при первом ответе.
- `cargo test --workspace --locked`: 8 тестов успешно. Проверены безопасный адрес API, SSE с кириллицей на границах байтов, LF/CRLF и комментарии, JSON fallback, ошибки HTTP 401/404/429/503, пустой/некорректный ответ, отмена, проверка SHA256 и удаление только собственных временных сеансов.
- `npm run test:ui`: 5 сценариев успешно в Chrome. Проверены отправка, streaming, Markdown и таблицы, все 9 языков CodeMirror, копирование кода/ответа, очистка/перезапуск без истории, смена ключа/модели/температуры, ошибки, отмена и окно 390×470. В этих тестах IPC подменён локальным тестовым транспортом; они не доказывают доступность провайдера.
- Отдельный `real_provider_smoke`: успешно через настоящий Rust HTTP-клиент, ваш приватный файл и API провайдера, модель `gpt-5.6-luna`. Получен потоковый Markdown с Python-функцией. Ключ и текст ответа не записывались в журналы. Модель `gpt-6-luna` во время проверки возвращала ошибки провайдера; она заменена в начальных настройках.

## Портативность

Release `CarCar.exe` собран с оптимизацией размера, LTO и статическим CRT, без установщика. Загрузчик собран отдельным Rust EXE. Запуск из CMD проверен: `carcar.cmd` → загрузчик → EXE из `%TEMP%\CarCar\runs\<UUID>`. Нативное окно открылось. При принудительном завершении главного процесса его временный профиль был удалён вспомогательным процессом; загрузчик удалил временный EXE.

Нативная тестовая сборка с feature `ui-test` проверена через WebView2 CDP: автозагрузка непустого ключа, отправка настоящего запроса, потоковый Python-код в CodeMirror, системное копирование кода, очистка диалога и обычное закрытие кнопкой. После завершения и папка профиля, и папка временного EXE отсутствовали. Релизные бинарные файлы собраны без этой feature.

Повторный запуск через CMD открыл пустой диалог; закрытие кнопкой прошло успешно. Первоначальная команда проверена именно в Windows PowerShell из CMD с настоящим GitHub Release: UTF-8-декодирование и закреплённый SHA256 сценария, загрузка обоих EXE, проверка контрольных сумм, открытие окна. Отдельно проверен загрузчик без локального CarCar.exe: он получил номер последнего релиза через GitHub API, скачал EXE по адресу версии, проверил SHA256 и открыл приложение. Ссылки на файлы версий используют уникальный параметр запроса, чтобы не получать устаревшие файлы CDN после замены assets. Обе скачанные тестовые копии затем завершены принудительно для проверки аварийной очистки.

GitHub Actions также успешно выполнил Windows-сборку и Rust-тесты. Итоговые публичные assets дополнительно сверялись локально; ключ не обнаружен в публичном архиве и исполняемых файлах.

## Ограничения проверки

Windows 10 x64 и совершенно чистая Windows без WebView2 на этой машине не проверялись. Ветка предложения установки WebView2 реализована, но установленный Runtime не удалялся ради теста. Нет цифровой подписи разработчика. Нет обещания очистить системные журналы, pagefile или буфер обмена Windows.

Для проверки нативного WebView2 предусмотрена отдельная feature `ui-test`, включающая тестовый CDP-порт 19347. Она не включена в release-команду, workflow или публикуемый EXE. API-ключ ни в тестовые исходники, ни в публичные файлы не включён.
